# Improvement study preregistration

Prepared on 2026-10-19, before any new improvement experiment. Phase 0 metadata validation subsequently passed in `phase0_setup.json`; training/inference remain NOT RUN. The decision rule below was frozen before the legacy-corpus exposure count.

## Scope and immutable evidence

The existing audit reports and JSONs are historical evidence. `baseline_snapshot.json` imports them verbatim with source hashes; it is not a new evaluation. New results must be produced by user-run scripts into this directory. Every numerical result in a report must cite its result JSON, N, interval method, and evaluation role. Planning constants below are design choices, not measured results.

The user runs terminal, training, inference, and verification commands using `.venv-ml`. Preparing scripts/docs does not constitute running them. All unexecuted work is `NOT RUN`. Do not edit the paper or open quarantined data. AI annotation files are excluded from training, tuning, model selection, and headline evaluation.

For supervised principle tasks every output must contain: **agreement with taxonomy-derived weak labels (partly AI-assisted mapping)**. Other stages must additionally identify their actual reference: human development labels with unconfirmed blinding; historical human company ratings with unconfirmed blinding; or a specified filing-derived proxy. A proxy is not human or independent semantic ground truth.

## Company split and encoder decision

- Keep `data/training_company_split/{train,val,test}.csv` and their existing CIN membership. Never regenerate, reassign, or replace the split to improve a result. Phase 0 hashes CSV bytes and checks CIN metadata only; it performs no prediction or performance calculation.
- The baseline JSON records test SHA-256 `079305b42510bed095c9bd937380a483951a76fbca42fb4ac10b55b4d829391d`. A mismatch fails setup and must be investigated, not silently accepted.
- The established test has already been evaluated repeatedly. Exactly-once evaluation is a prospective rule for new configurations in this study, not a claim that this is a fresh historical test cohort. Record inherited access counts/times as unknown rather than inventing them.
- **User decision on 2026-10-19, refined before counting exposure:** audit the exact saved legacy MLM corpus against the frozen CIN sets first. If any corpus sentence is attributable to a validation or test CIN, create a train-company-only adapted encoder and use it as the base for all new Stage 3 candidates regardless of whether validation macro-F1 decreases. This is **leakage control**, not an accuracy improvement. If the attributable count is zero, skip repeated MLM only when the entire saved corpus reconstructs from the current database and the legacy checkpoint can be tied to that exact corpus; otherwise provenance stays unresolved and train-only MLM remains the default. A zero match in an incomplete current database is insufficient to clear the legacy checkpoint.
- The legacy corpus is globally deduplicated and has no CIN field. Count each unique sentence once; report validation-associated and test-associated counts, their union, exclusive counts, shared-with-train counts, unmatched sentences, and the DB reconstruction check. Shared boilerplate belongs to multiple CIN cohorts and must not be silently assigned to train alone. Current DB attribution is evidence about the saved corpus, not proof of the exact historical checkpoint's training input if that provenance is missing.
- **Frozen train-only corpus rule (set before its construction):** use only sentences already present in the saved legacy corpus whose current-DB attribution mask is *train and no other cohort*. This excludes exact boilerplate also filed by validation/test companies, as well as 25 current-DB sentences absent from the saved historical corpus. The latter exclusion keeps the old/new MLM input universe comparable. Save the selected text count, all train and contributing CIN lists, their hashes, excluded shared-text counts, input/output hashes, DB snapshot metadata, and assertions in a write-once JSON manifest. Do not read labels or performance metrics during corpus building.
- Compare the legacy and train-only bases on the same frozen **validation** split under an otherwise matched classifier recipe. Baseline historical test numbers remain labeled as prior results. Score only the final selected new configuration once on test. A controlled old-base-versus-new-base test delta is unavailable unless both matched classifiers have legitimately cached test predictions; do not infer a base effect from the historical seed-99 versus a newly trained classifier.
- New train-only MLM corpus construction must filter by the frozen train CIN allowlist before collecting texts, persist corpus text hashes and contributing CINs, and assert no validation/test CINs were used. Use train-company data only for fitting token statistics, preprocessing vocabularies, and learned masking dictionaries. The externally pretrained base tokenizer remains fixed.
- Corpus membership for the old domain-adapted checkpoint is unresolved. Source code alone proves the builder can read all companies; it does not prove which exact texts a historical checkpoint saw. Keep that caveat when comparing old and new encoders.
- Initial MLM design: cached `bert-base-uncased` revision `86b5e0934494bd15c9632b12f734a8a67f723594`, two epochs, learning rate 1e-5, max length 256, MLM probability 0.15, microbatch 4, gradient accumulation 8, seed 42, fp16 on CUDA, dynamic padding and gradient checkpointing for the 4 GB GPU. Use the fixed final epoch, with no MLM checkpoint choice on outer validation/test text. All encoder saves require reload and exact tensor-by-tensor state comparison; record any loader alias warnings rather than silently accepting a partially restored state.

## Shared reporting and selection rules

- Record actual `git rev-parse HEAD`, tracked worktree-diff hash, script/config hashes, package versions, Python executable, seeds, GPU name/memory, corpus hashes, split hashes, and UTC timestamps in each new result JSON. A dirty checkout must not be described solely by a clean Git hash. Missing metadata is explicit, never inferred.
- Fixed classifier output order is P1 through P9. Macro-F1 is over these nine labels with zero-division=0. Also report per-class supports and flag unsupported classes; unsupported-class zeros are not semantic failure evidence.
- Classification primary metrics: Top-1, Top-2, nine-class macro-F1; source-wise B/C/Notes and the predeclared union B+Notes. Multi-label targets remain a separate exploratory task and cannot replace single-label headline accuracy.
- Use percentile CIN-cluster bootstrap, 2,000 replicates, seed 4206, 95% intervals. Resample companies with replacement and retain all their rows. For paired differences resample the same companies for both configurations. Save row IDs, CINs, labels, logits/probabilities, selected predictions, resample seed, valid/undefined replicate counts, and subset definitions. Empty subsets yield null metrics with a reason.
- One rating per company makes company resampling equivalent to row resampling for the historical Stage 6 cohort. Preserve its old interval method in the baseline import; do not relabel old intervals as new 2,000-replicate estimates.
- Counts, fixed formula weights, configuration constants, and operational API responses are descriptive and have no performance CI. If a CI is missing in historical artifacts, mark it missing. Never manufacture it from rounded summary statistics.
- Every attempted configuration has a ledger row, including failures, unchanged and worse results. Persist failures before reporting them. Write the planned configuration before training, not after seeing validation scores.

## Prospective test access

Development scripts must not load test labels, test predictions, or test metrics. Metadata checks may read the test file only for hashing and CIN disjointness and must be logged as `METADATA_ONLY`, not evaluation. Existing audited concept ID lists may be imported without regenerating a holdout from test outcomes.

Before a final scoring call: freeze config and model/ensemble/calibration hashes, reserve its test-access entry, and write UTC time, exact test hash, role, and output path. Persist logits once and compute all metrics/subsets/CIs from that cache. A failed scoring attempt stays in the log; do not erase or automatically repeat it. Refuse a second evaluation of the same frozen configuration. Inference with a recovered old comparator is also an access; do not pretend it has never been evaluated.

No cached row-level baseline predictions were located in the inspected results/model paths. Aggregate JSONs cannot support an old-vs-new paired bootstrap. Until an original matching prediction cache is recovered, old-vs-new tables report source-backed old estimates and new estimates/CIs, with paired old-vs-new CI `NOT AVAILABLE`. Do not rerun the old baseline just to fill that field under the exactly-once rule. Paired comparisons among newly preregistered methods can use their single saved evaluation each. A separate authorized protocol amendment is required for any additional legacy-reference inference.

## Phase 1 — Stage 3 validation experiments

Start from the new train-only domain-adapted encoder after Phase 0 has passed. All checkpoint/seed/ensemble/threshold choices use validation data only. Primary final selection is highest nine-class macro-F1 on the unmodified company-disjoint validation split. Tie tolerance is 1e-8; ties prefer the single model, then lower compute, then lexicographic config ID. A new configuration must strictly beat the recovered baseline recomputed on the same validation rows to replace the operational baseline. If none does, retain the baseline and report no validation improvement.

The first supervised control compares the train-only MLM encoder and the legacy MLM encoder under **the same seed-42 recipe and frozen validation rows**. Each base gets five epochs, LR 2e-5, batch 4/accumulation 4, max length 512, square-root-balanced class weights, weight decay 0.01, 300 warmup steps, cosine decay, and best-epoch selection by nine-class validation macro-F1. The legacy run is a diagnostic historical-encoder comparator and may have transductive pretraining exposure; it cannot become the new leakage-controlled base. Both runs save row-aligned validation logits and 2,000-resample CIN intervals. Neither run reads the test labels or scores test. Normalize and strictly load all LayerNorm aliases from the MLM checkpoint before training; strictly restore and tensor-check the selected supervised checkpoint after training. This controlled validation comparison is separate from the old seed-99 recovered operational baseline and its already-observed test result.

Register these bounded candidate families before their first run; no test-driven expansion:

| Family | Planned validation-only choices |
|---|---|
| Control | Train-only DAPT + BERT, LR 2e-5, five epochs, validation macro-F1 checkpoint selection, seed 42; microbatch 4 with accumulation 4; max length 512 |
| Section C masking | Per-example augmentation probability 0.15 or 0.30. Eligible template/question phrases are derived from train concepts/text only; never feed concept ID/source/gold principle as model input. Preserve original text targets, never mask validation/test. Log mask frequency. |
| Section B weighting | Multipliers 1, 2, 4; apply either loss weighting or source-aware sampling in separate candidates, not both by default. Natural unweighted validation distribution selects the winner. |
| ClimateBERT | Named ClimateBERT encoder, train on the same frozen train rows. Check actual architecture/tokenizer instead of assuming BERT LayerNorm names. |
| Soft vote | BERT/ClimateBERT alpha in {0, 0.25, 0.5, 0.75, 1}; choose alpha by validation macro-F1 and archive the complete val table. |
| Existing multi-seed ensemble | Uniform soft vote across the five historical seeds after strict restoration of every selected checkpoint. Treat as a historical-encoder candidate with possible unsupervised corpus exposure, not a train-only adaptation result. |
| Regularization | Label smoothing in {0, 0.05, 0.10}; separate R-Drop coefficient in {0.1, 0.5}; no unregistered factorial combination. |
| Long text | Window length 512, overlap 128, pooling {mean logits, mean probabilities, max probabilities followed by renormalization}; compare to truncation on validation only. |
| Calibration | Positive scalar temperature fit by validation negative log likelihood; ECE uses 15 equal-width bins. Temperature is a calibration step, not an expected Top-1 improvement. |
| Selective prediction | Choose threshold by maximum validation coverage whose CIN-bootstrap accuracy lower bound is at least 0.95. If none qualifies report none; never optimize test threshold. Report test coverage, accepted/abstained N, accuracy and CIs together. |

To control compute, families are independent single-factor candidates around the control; do not silently combine winners. Any combined candidate needs a frozen config/ledger entry before training. Use fp16 only on supported models; gradient accumulation and dynamic padding for the target GPU; no DeBERTa-v3 fp16 run.

Concept-disjoint masking is a separate diagnostic track with the existing frozen concept lists for holdout seeds 42/17/73. For each concept list, train excludes those concepts across all sources. Validation for selecting its diagnostic model consists of **held-out concepts in validation companies**, not the original scripts' seen-concept-only validation. Test remains company-disjoint and includes the same held-out concepts only. Concept linking ambiguities/unmatched entries must follow a frozen, documented rule before metrics; no sample removals based on prediction correctness. Do not use the existing test scores to choose concept lists, mask vocabulary, probability, or seeds.

The winning diagnostic setting is chosen by mean validation macro-F1 across the frozen concept holdouts; it does not override the main full-validation winner. Score each selected diagnostic config once on its frozen concept-test subset and cache. Report per-holdout N/CIN/support and bootstrap CIs plus cross-holdout mean/sample SD. SD is not a confidence interval. Because held-out-company wording may still enter train-only MLM for concepts appearing in train companies, state whether concept disjointness applies to supervised training only. A strict concept-novel MLM claim requires purging those concepts from its encoder corpus too.

**Success:** improved full-validation macro-F1 for the main model; improved concept-disjoint validation performance for the diagnostic model. Test improvement is a reported outcome, never a tuning objective or a reason to start another search. A claim of paired improvement needs a valid paired CI; otherwise report descriptive changes only.

## Phase 2 — Stage 5 method comparison

Use identical company split, row IDs, preprocessing and weak labels across methods. Learned components fit only on train companies. Register BGE-base zero-shot, contrastive bi-encoder, TF-IDF + multinomial logistic regression, frozen-embedding + logistic regression, and the selected Phase 1 model. Zero-shot is explicitly zero-shot; trained methods receive the same train-label access. Do not describe them as the same supervision regime or a causal compliance gain.

Before this phase's runs, freeze embedding model/revision, principle texts, contrastive pair construction and mining scope, optimizer settings, and a bounded validation grid. Planned logistic C grid is {0.1, 1, 10}; class weighting is {none, balanced}; vectorizer/normalizer fit on train only. Contrastive negatives and any learned anchors cannot use validation/test examples. Validation macro-F1 selects settings independently per method. Main metrics match Phase 1; paired CIN-bootstrap deltas on identical test caches. Predeclared subgroups are B, C, Notes and B+Notes, with all their Ns reported.

A method evaluated on a concept-disjoint subset needs a separate train/validation fit purged of that holdout's concepts. Merely filtering the test subset for a full-concept-trained baseline does not make that baseline concept-disjoint. Preserve the full-concept comparator label when reporting it.

**Success:** transparently compare trained/zero-shot methods, report stronger validation/test agreement if observed, and retain every unsuccessful baseline. No requirement that all methods beat the existing result. Reuse Phase 1 cached predictions for the same model/test rows rather than evaluating it again.

## Phase 3 — Stage 4 without new human raters

Only historical batches with human development labels are eligible. Keep their unconfirmed blinding and prior detector-tuning exposure. Resolve CINs using stable identifiers; missing/ambiguous company links cause a documented setup failure, not a segment-split fallback. No Batch 3 or AI labels enter fitting or evaluation.

Register deterministic outer five-fold and inner three-fold stratified group CV by CIN, seed 42. Confirm group/class feasibility before fitting; if infeasible, stop and preregister an amended fold count rather than trying seeds until scores improve. All trainable features, imputation, normalization, hyperparameters, probability calibration and decision thresholds fit inside the outer training folds, with inner-fold selection only. Freeze feature list before labels are scored: hedging density, semantic margin, KPI flag, numeric density, URL/evasion flag, statutory-term flag, and length. Feature generation must not call the historical `model_flagged` label fields.

Compare the frozen rules, regularized logistic regression (C {0.1, 1, 10}) and small gradient boosting (depth {1, 2}, estimators {25, 50}, learning rate 0.05). Inner selection maximizes ROC-AUC; decision threshold maximizes inner OOF F1 over {0.1, 0.2, ..., 0.9}. Produce one outer OOF prediction per eligible row. Report continuous-score ROC-AUC, average precision (named as AP), F1, precision/recall, calibration, N/CINs and cluster CIs. Frozen binary rules have no continuous score: report their balanced accuracy separately, or a preregistered continuous margin explicitly as a new scoring function. They were developed on the whole cohort, so their OOF-looking numbers remain an optimistic historical comparator.

**Filing-consistency proxy:** establish filing year, reporting boundary, units, dimensions, applicability, explicit quantified claim and independently mapped matching numeric fact before comparisons. Zero is a valid measurement, not absence. Missing, non-applicable, unparseable and unresolved links are separate statuses. No automatic mapping from a generic topic mention to an unsupported-claim gold label. Freeze eligibility and matching rules before scoring, report full denominator/linkability flow, and compare independently derived indicators without reusing the exact detector rule as its own reference. Even then call this filing-consistency/proxy agreement; it does not establish greenwashing precision/recall or independent semantic truth. If an independent reference cannot be constructed, precision/recall is `NOT AVAILABLE` and only mismatch/linkage counts are reported.

Any numeric-removal/hedging perturbation design is frozen before execution, pairs each eligible source narrative with its perturbation, and reports monotonic score changes and company-bootstrap CIs as **synthetic sensitivity**, not accuracy.

**Success:** sound company-grouped OOF development evidence and interpretable continuous scoring, with improvements reported only where observed. Human-independent greenwashing validation remains unavailable.

## Phase 4 — Stage 6 construct/stability evidence

Retain the existing historical-human fixed-formula correlation and its provenance, blinding uncertainty and extraction artifacts. Do not replace the original human scores with AI annotations. Human-score weight fitting, if attempted at all, is exploratory nested leave-one-company-out with all tuning inside each outer training fold and includes every company.

Use the fixed project heuristic weights (0.40, 0.30, 0.20, 0.10); the local code attributes them to the project report. Calling them SEBI-prescribed requires an exact authoritative citation that is not established by this audit. Do not change the formula during this phase in search of better human correlation.

- Objective proxy associations: assurance flag, numeric fact share, BRSR Core coverage, sector effects. Freeze proxy extraction and applicability before outcomes. Report N/CIN, missingness, raw and sector-adjusted associations and cluster CIs. An overlapping component/proxy correlation is internal consistency and may be mechanically induced. Add leave-one-component-out sensitivities where relevant, explicitly naming the dependency; never present these as independent accuracy.
- Weight sensitivity: seed 42, 1,000 Dirichlet draws, concentration 100 times the fixed weight vector. Report Spearman/Kendall relative to baseline ordering and top-quintile membership retention, plus CIN-bootstrap uncertainty. Draw-to-draw variation is weight sensitivity, not a bootstrap CI or evidence that weights are correct.
- Rank variability: deterministic per-company scores have no individual rank sampling CI by themselves. CIN resampling can quantify empirical peer-percentile variation for a fixed target against resampled peers. If within-filing uncertainty is modeled, preregister fact/context resampling units and dependencies. Report small-sector/undefined intervals, not invented rank precision.
- Components: variance, missingness, pairwise correlations, VIF. Zero variance/singular covariance yields undefined VIF with an explicit flag. Inspect SDG saturation and dependence on the same taxonomy universe; do not tune the component to improve human agreement.
- URL inspection: freeze a content-based criterion before recomputation, keep the old-score cohort and all companies, and preserve both old and corrected deterministic versions. Fixing an extraction artifact changes the score version; it does not create a new independent human evaluation. Preserve the original historical-human headline under its original score version.

**Success:** reproducible stability and construct evidence, detection/repair of code artifacts where justified, and honest no-improvement reporting. No claim that proxy/rank stability increases human-validated accuracy.
